# 第二轮设计出发点：让学习和维护都围绕真实问题

## 从读者要完成的事出发

第一章留下了一个具体对象：C₁₂ 中 H={0,4,8} 的四个陪集。第二轮首先要让初学者回答“群元素能否搬动这些位置，搬动时丢掉了什么信息”。本轮交付因而是一章可连贯阅读的正文和一个可操作的实验，而不是继续扩张框架或先列全书大纲。

原项目的核心能力值得保留：Quarto 管理教材、MathJax 排公式、原生 JS/SVG 展示小实验，极小事件索引只发布已写好的证明。没有证据表明它需要前端框架、通用群论软件或额外知识库。本轮只改变阅读、验收、研究交接确实需要改变的地方。

## 为什么采用这样的发现顺序

陪集左乘先于抽象群作用定义。读者已经认识“一个位置有多个名字”，现在必须验证换代表元不改变结果；良定义就成为解决当前问题的步骤。由此再给每个群元素配一个置换，作用公理才有可以指认的对象。

三角形带来第一章没有的非交换性。置换按右边先做的约定合成，左陪集一直用 xH，作用一直写作 g·(xH)=(gx)H。选择 S₃ 中固定顶点 1 的 H=⟨(23)⟩，使 xH 对应 x(1)，把实际陪集和顶点连接起来。这比先讲抽象置换群再寻找例子更容易解释“位置与操作不是同一角色”。

轨道与稳定子回答两个互补问题：哪里可以到达，哪些操作让当前位置不动。轨道—稳定子公式由陪集到轨道的双射证明，计数来自此前证明的陪集等大与划分，不把拉格朗日定理藏作默认知识。传递作用与陪集作用的对应再说明这个模型具有一般性。

作用核回答“哪些操作在整个舞台都不可见”。把核写成所有点稳定子的交，再写成所有共轭 xHx⁻¹ 的交，正规性与忠实性就来自同一个问题。此时单性只排除正规子群，不能排除一般真子群；这是从循环群走向非交换群必须澄清的区别。

μ=d 放在这些工具之后。任意忠实作用先取一个非单点轨道，给出 μ≤d；单群最小指数的陪集作用再给出 d≤μ。两边所用的作用不必事先传递，避免把待证结论放进定义。阶数整除 n! 的限制由嵌入自然产生，五点问题只留下下一次真正需要的证明，不提前宣称 A₅ 单性已完成。

## 实验只承担能看见的事情

陪集舞台选择同为三点的 C₆ 与 S₃。前者取 H={0,3}，加 3 在三个陪集上都看不见；后者取 H=⟨(23)⟩，每个非单位元至少移动一个顶点。同样大小的舞台展示不同大小的核，能直接修正“传递必忠实”的误猜。

界面显示作用前后的对应、实际陪集成员、选定点的稳定子和全局核，读者可以逐项核对。单个元素反复作用的轨迹与整个群的轨道分别说明，避免把第一章一个步长的循环误当成任意群的全部可达位置。有限数学核与界面分开，测试从另一种小模型核对作用规律。

独立 HTML 页面便于单独教学和测试；章节嵌入它，同时保留静态计算与直接入口。实验不用 MathJax，文字在脚本关闭时仍可阅读，原生控件支持键盘和手机。这些安排各自解决实际用例，不要求搭建新的应用运行时。

## 文档各自负责什么

旧 README 同时容纳读者入口、首次安装、Windows 和 Linux 差异、云端故障、Pages 权限、研究规则与历史验收，找“怎么读”或“怎么验收”都要跨过很多无关内容。旧 AGENTS 仍以“仓库最初只有两个文件”的初始化指令为主，接续时容易把已完成工作当作待办。

本轮 README 保留阅读、安装、一个日常验收入口与研究入口；AGENTS 更新为当前协作约定，保留数学驱动、证据区分、轻量技术栈和分支隔离。没有把 gpt-human-style 六个习惯复制成项目检查表。

NOTICE 集中共通的能力边界与记号；HELP 接住安装差异、模块本地打开限制、端口、导航不出现、未合并分支与云端恢复等按需问题。正文仍就影响具体推理的条件当场解释，例如有限性、单性与 A₅ 只是预告；这些不是应移走的通用免责。试读尚未实际发生也仍在材料和审查摘要直接说明。

research/state.md 用来说明当前成果与下一步；历史事实由提交及 PR 取回，不把每轮安装叙述继续堆到当前入口。本文解释本轮取舍，不成为每次工作必须填写的新模板。

## 为什么保留这些验收

循环群参数和小子群枚举继续使用，陪集实验增加作用、稳定子、核与复合方向的有限核对。内容索引检查保护研究／教材边界；站内检查覆盖独立实验和章节链接；浏览器检查验证桌面、窄屏、键盘、静态阅读与嵌入。它们能发现的错误不同，因此都保留。

日常只需 `python scripts/project.py verify`，内部复用测试、构建和浏览器命令，不另写第二套验收逻辑。有限模型只说明实现与例子符合核对；正文一般证明由数学审读检查。模型可以发现跳步，但试读仍要交给真实初学者，未收到反馈时不把模型意见计作真人数据。

实际云端验收随后复现了旧容器的 Yarn 软件源签名故障，浏览器依赖尚未安装就中止。于是只修这个已观察到的环境问题：采用官方 Node feature v2，关闭不需要的 Yarn APT 安装路径；保留签名校验。容器工作流也改为调用同一个 verify 入口，使新增的内容边界测试不会在容器里遗漏。这项改动来自实际失败，不是为了预防假设中的情况而增加新关卡。
